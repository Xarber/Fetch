Self-hosted server

Obtain the authorized source checkout first. You need Python 3.11+, FFmpeg and FFprobe; Node 22+ is used when changing the web frontend. Deno is recommended for extractors that require JavaScript challenges. X-Center is the project's default private hosting target.

Choose a unique administrator password during configuration. The following commands preserve existing configuration rather than overwriting it.

python3.13 -m venv .venv
.venv/bin/pip install -r requirements.lock
.venv/bin/pip install -e '.[test]'
.venv/bin/python scripts/configure.py
.venv/bin/python scripts/run.py init
.venv/bin/python scripts/package_source.py
.venv/bin/python scripts/run.py api

Run the worker in another terminal:

.venv/bin/python scripts/run.py worker

Open the workspace on the server's configured address and sign in as admin. No default password is provided.

Docker option

FETCH_COMMIT="$(git rev-parse HEAD)" docker compose build
docker compose up -d
docker compose ps

Keep the service private. Use a trusted HTTPS endpoint for access from another device, or an SSH tunnel to a loopback-only deployment. Select an unused local port on X-Center; never stop another service to claim its port.

iPhone & iPad source

The existing SwiftUI client is retained because the project specification prioritizes native background URLSession, App Groups, the Share Extension, Keychain and file integrations. Expo remains the default for new mobile work; this update does not rewrite the existing client merely to change frameworks.

Open ios/Fetch.xcodeproj in an installed Xcode. Select your own development team for both Fetch and FetchShare. Register the shared App Group or consistently change its identifier in both targets and source. Target iOS/iPadOS 17 or later.

xcodebuild -project ios/Fetch.xcodeproj -scheme Fetch \
  -configuration Debug -sdk iphonesimulator \
  -destination 'generic/platform=iOS Simulator' \
  -derivedDataPath build CODE_SIGNING_ALLOWED=NO build

No signed app is published. An unsigned device IPA requires an authorized signing and installation workflow. A simulator bundle is not a device IPA. Source-level checks and browser tests do not establish native functionality; physical device and background lifecycle tests remain required.

Privacy & licensing

Submitted media URLs go to the server you configure. The original source observes its requests. Browser credentials remain in memory; native credentials are stored in Keychain. Ideas are local until explicitly exported. The service worker never caches private API responses or media.

Download only content you own or have permission to save. Source availability is not permission. Fetch does not implement DRM, paywall or account-access bypasses.

Original Fetch code and branding are AGPL-3.0-only. Third-party components retain their notices. The older Expo starter has its original MIT notices; repository reuse must preserve those notices and history. Sign in to the workspace and choose About Fetch → Download corresponding source for this server's prepared source archive.

Development status

The backend and browser workflow have automated checks using generated authorized fixtures. These are not tests of every supported website, a native release, or certification of an Internet-facing deployment. The source repository's docs/reports/ records executed checks and outstanding work.
